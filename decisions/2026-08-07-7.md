# 2026-08-07 — Registration codes (restricted signup) + member role

Implemented admin-issued, one-time-use registration codes that gate signup, and
a `members.role` column to distinguish admins.

## What changed
- **DB (015)**: `ALTER members ADD role` (default `member`); promotes the seeded
  admin `shakya1221@gmail.com` to `admin`; new `registration_codes` table and
  four plpgsql/sql functions:
  - `register_member_with_code` — atomically consumes one code inside a txn.
  - `create_registration_code` (auto 8-char code when blank), `list_registration_codes`, `delete_registration_code`.
- **Domain/Repository**: `RegistrationCode` types, `RegistrationCodeRepository`
  interface, sentinel errors `ErrInvalidRegistrationCode` /
  `ErrRegistrationCodeUsed` / `ErrForbidden`.
- **API**: registration requires a `code`; new admin-only
  `/api/registration-codes` endpoints guarded by new `RequireRole("admin", auth)`
  middleware; member responses now include `role`.
- **Repo**: 7-column scans (`role` added) for `get_member_by_email`/`get_member_by_id`.
- Wired in `router.go`/`main.go`.

## Why
Prevent open registration; only admins can grant access via one-time codes.
Each code is consumed at first use so it cannot be reused.

## Fixes found during backend test pass
- `CREATE OR REPLACE` cannot change return types → DROP + CREATE.
- PL/pgSQL OUT-column ambiguity in `RETURNING`/`WHERE` → table-qualified columns.
- `'member'` literal typed `text` → cast to `varchar`.
- `DELETE ... RETURNING INTO` null on zero rows → IS NULL guard.
- NULL UUID/email from `list_registration_codes` → COALESCE to `''`.
