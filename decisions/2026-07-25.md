# Events feature

## What
Added a calendar event system with visibility control. Events have start/end times, description, status, and a created_by reference. An event_viewers join table controls which members can see events they didn't create.

## Why
The frontend calendar needs event data. Events should be private by default — only the creator and explicitly added viewers can see them.

## Key decisions
- Used an event_viewers junction table (event_id, member_id) instead of a permission level field to keep it simple and normalized
- list_events_by_month accepts a member_id and returns events where the member is either the creator or a viewer
- end_time is required (NOT NULL) to simplify calendar rendering on the frontend
- All event endpoints require authentication; event mutations require ownership
