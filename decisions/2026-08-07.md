# Backend E2E workflow (Phase 2)

## What
Added `.github/workflows/e2e.yml` to the backend repo that runs the full-stack Playwright E2E suite on push to `main`/`dev` (and via `workflow_dispatch`).

## Why
The frontend repo owns the Playwright E2E suite. The backend must also validate end-to-end behaviour whenever the backend changes. This workflow reuses the frontend suite (checked out from its `dev` branch) instead of duplicating it: same harness, one source of truth.

## How
- Runner's own checkout = backend under test; built + served by `frontend/scripts/start-backend.sh` via `E2E_BACKEND_DIR=${{ github.workspace }}`.
- Frontend checkout at `frontend/` (dev); deps installed; Playwright browser installed.
- Postgres 16 service with `POSTGRES_DB=productdb_e2e`; migrations run by the backend at startup; data truncated by the suite's globalSetup. Uploaded media go to a temp `MEDIA_ROOT` removed in globalTeardown.
- `psql` client installed so `start-backend.sh` can ensure the database exists.
- Artifacts (playwright-report, test-results) uploaded on failure.
