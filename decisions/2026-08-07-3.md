# Require E2E tests for backend changes + local E2E run

## What
- Added an Agent rule to `backend/AGENTS.md` requiring Playwright E2E validation for backend changes that alter user-facing behavior.
- Confirmed the E2E CI workflow (`.github/workflows/e2e.yml`) and ran the Playwright E2E suite locally against the current backend.

## Why
Backend changes that change API/auth/session/media behaviour should not only pass Go tests — they must be validated against the real cross-repo frontend E2E suite, so the running backend stays compatible with the frontend. A rule makes this a merge gate instead of an optional step.

## Rule added (backend/AGENTS.md)
Under "Agent rules": backend changes affecting user-facing behavior must pass the Playwright E2E suite before merge — run locally via `frontend/scripts/start-backend.sh` + `npx playwright test`, or rely on `.github/workflows/e2e.yml`.

## Key decisions
- Rule scoped to the backend project AGENTS.md only (frontend repo owns the Playwright suite; the backend consumes it).
- Local E2E runs the same harness the CI workflow uses: `start-backend.sh` builds+serves this backend on `:8090` against `productdb_e2e` Postgres, `npm run dev` serves the frontend on `:5173`.
