# Seed an admin member via migration

## What
Added `db/migrations/014_insert_admin_member.up.sql` to insert a member:
- email: `shakya1221@gmail.com`
- name: `admin`
- password: `swty0305` (stored as a bcrypt hash, `bcrypt.DefaultCost`)

The insert uses `ON CONFLICT (email) DO NOTHING` so rerunning does not error.

## Why
A seeded admin account is needed without going through the registration flow. The `members.password` column stores a bcrypt hash (matching what `RegisterMember`/`LoginMember` in `src/api/member_handler.go` produce), so the login endpoint can authenticate this account as-is.

## Key decisions
- No `.down` migration (consistent with the rest of `db/migrations/`, which has no down files).
- Password bcrypt hash generated with `bcrypt.DefaultCost` and verified via `bcrypt.CompareHashAndPassword` against `swty0305`.
- Idempotent upsert on the unique email column.

## Changes
- `db/migrations/014_insert_admin_member.up.sql` (new)

## Validation
- Applied the schema (`001`, `002`) + `014` to a throwaway Postgres DB: `INSERT 0 1`, row `shakya1221@gmail.com / admin / $2a$10$...` created, no error.
- Confirmed the stored hash verifies against the plaintext password with bcrypt.
- The app runs all embedded `*.up.sql` via golang-migrate (`main.go` embeds `db/migrations/*.up.sql`), so `014` is applied automatically on startup.
